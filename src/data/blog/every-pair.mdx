## Background

### The force

Every body pulls on every other with Newton's gravity, softened:

$$
\mathbf F_{ij} = G\, m_i m_j \, \frac{\mathbf r}{\left(|\mathbf r|^2 + \varepsilon^2\right)^{3/2}}, \qquad \mathbf r = \mathbf x_j - \mathbf x_i
$$

- $G$ is the gravitational constant, $m_i$ and $m_j$ the two masses,
  $\mathbf r$ the vector from body $i$ to body $j$.
- $\varepsilon$, the **softening**, keeps two bodies passing close from getting an
  enormous kick in one step and flinging apart: below about
  $\varepsilon$, the force stops growing.
- Each pair is computed once: the force on $j$ is the force on $i$, reversed
  (Newton's third law). For $n$ bodies that's $n(n-1)/2$ pairs: at 4,096
  bodies, **8,386,560 pairs a step**, 60 steps a second.

Per pair: a subtraction for $\mathbf r$, a sum of squares, one **square root**,
one **division**, and a few multiplies to scale $\mathbf r$ and add the result
to each body. The square root and division are the expensive part.

### The technique: SIMD

A CPU's vector (SIMD) instructions do the same operation on several
numbers at once: one `fsqrt.4s` takes four square roots. If four pairs'
worth of numbers sit side by side, four pairs cost about what one did.

- Vector width depends on the hardware: 128 bits (four `f32`) on ARM's
  NEON, in WebAssembly's `simd128` and in baseline x86-64; 256 bits with
  AVX2; 512 with AVX-512.
- The compiler does the vectorizing (no intrinsics here); the work is
  arranging the loop so it can.
- **The catch: the sum.** Body i's total force is a sum over every
  other body. Floating-point addition isn't associative, so adding in a
  different order gives different last bits, and the compiler won't
  reorder it on its own. The engine's results must be bit-identical
  natively and in WebAssembly, so the new order is written into the
  source: body i's sum is kept in 16 partial sums ("lanes"), added
  together in a fixed order at the end.

## The loop, before

The hot loop as the compiler built it before: `f32`, Apple M4 (AArch64).
**One pair per iteration.** The 2-wide vectors (`.2s`) hold only that
pair's x and y; the square root and division are scalar (`fsqrt s16`,
`fdiv s5`); and `fcmp s5, #0.0` / `b.eq` is a branch that skips two
bodies sitting exactly on top of each other with no softening (0/0).

```asm
LBB193_57:
	cmp x1, x15
	b.eq LBB193_53
	mov x16, x15
	add x15, x15, #1
	ldr d4, [x11, x17]
	fsub.2s v4, v4, v1          ; r = x_j - x_i  (x and y)
	fmul.2s v5, v4, v4
	faddp.2s s5, v5             ; |r|²
	fadd s5, s9, s5             ; + ε²
	add x17, x17, #16
	fcmp s5, #0.0               ; coincident? skip the pair
	b.eq LBB193_57
	add x17, x12, x16, lsl #4
	ldp s7, s6, [x17, #8]
	fmul s7, s3, s7
	fsqrt s16, s5               ; one square root
	fmul s5, s5, s16
	fdiv s5, s7, s5             ; one division
	fmul.2s v4, v4, v5[0]       ; the force
	fmul.2s v5, v4, v2[0]
	fadd.2s v0, v0, v5          ; body i's sum, in order
	fmul.2s v4, v4, v6[0]
	ldr d5, [x13, x16, lsl #3]
	fsub.2s v4, v5, v4
	str d4, [x13, x16, lsl #3]  ; body j's share
	b LBB193_56
```

## The loop, after

The same work, **four pairs per iteration** (`.4s`): four square roots
and four divisions in one instruction each. The branch became a select
(`fcmeq` and `bic` zero the coincident pairs' force), `ld2` / `st2` split
and rejoin the bodies' x and y, and each pair's force is kept (`str`) for
a second pass that adds body i's sum in its 16 lanes.

```asm
LBB95_8:
	ldr q7, [x17], #16          ; four bodies' x
	ldr q16, [x0], #16          ; four bodies' y
	ldr q17, [x1], #16          ; four masses
	ldr q18, [x3], #16          ; four inverse masses
	fsub.4s v7, v7, v4          ; four r.x
	fsub.4s v16, v16, v5        ; four r.y
	fmul.4s v19, v7, v7
	fmul.4s v20, v16, v16
	fadd.4s v19, v19, v20       ; four |r|²
	fadd.4s v19, v6, v19        ; + ε²
	fmul.4s v17, v17, v2[0]
	fsqrt.4s v20, v19           ; four square roots
	fmul.4s v20, v19, v20
	fdiv.4s v17, v17, v20       ; four divisions
	fcmeq.4s v19, v19, #0.0     ; coincident?
	bic.16b v17, v17, v19       ;   then no force (a select, not a branch)
	fmul.4s v7, v7, v17         ; four forces, x
	fmul.4s v16, v16, v17       ; four forces, y
	fmul.4s v17, v18, v7
	ld2.4s { v19, v20 }, [x16]  ; four bodies' accelerations (x, y)
	fsub.4s v21, v19, v17
	fmul.4s v17, v18, v16
	fsub.4s v22, v20, v17
	st2.4s { v21, v22 }, [x16], #32  ; body j's share, four at once
	str q7, [x4], #16           ; the forces, kept for body i's sum
	str q16, [x5], #16
	subs x6, x6, #4
	b.ne LBB95_8
```

## Benchmarks

4,096 bodies, one call of the gravity loop (8.4 million pairs), before →
after. Native builds are the default (baseline) build unless noted;
"wasm" is the same Rust compiled to WebAssembly with `simd128`, run by
wasmtime or by V8, Chrome's engine (Node).

| Machine                   | Build           | `f32`                  | `f64`                   |
| ------------------------- | --------------- | ---------------------- | ----------------------- |
| AMD Ryzen 7 9700X (Zen 5) | native          | 13.42 → 4.68 ms (−65%) | 18.74 → 10.88 ms (−42%) |
|                           | native, AVX2    | 13.16 → 2.79 ms (−79%) | 18.70 → 6.67 ms (−64%)  |
|                           | native, AVX-512 | 13.14 → 1.58 ms (−88%) | 18.75 → 3.20 ms (−83%)  |
|                           | wasm, wasmtime  | 14.35 → 4.67 ms (−67%) | 18.72 → 10.92 ms (−42%) |
|                           | wasm, V8        | 22.23 → 4.72 ms (−79%) | 18.72 → 10.88 ms (−42%) |
| Apple M4                  | native          | 8.77 → 4.28 ms (−51%)  | 8.72 → 8.61 ms (−1%)    |
|                           | wasm, wasmtime  | 10.52 → 4.43 ms (−58%) | 9.82 → 8.71 ms (−11%)   |
|                           | wasm, V8        | 10.55 → 4.33 ms (−59%) | 10.65 → 8.30 ms (−22%)  |

## Background

### The force

Every body pulls on every other with Newton's gravity, softened:

$$
\mathbf F_{ij} = G\, m_i m_j \, \frac{\mathbf r}{\left(|\mathbf r|^2 + \varepsilon^2\right)^{3/2}}, \qquad \mathbf r = \mathbf x_j - \mathbf x_i
$$

- $G$ is the gravitational constant, $m_i$ and $m_j$ the two masses,
  $\mathbf r$ the vector from body $i$ to body $j$.
- $\varepsilon$, the **softening**, keeps two bodies passing close from getting an
  enormous kick in one step and flinging apart: below about
  $\varepsilon$, the force stops growing.
- Each pair is computed once: the force on $j$ is the force on $i$, reversed
  (Newton's third law). For $n$ bodies that's $n(n-1)/2$ pairs: at 4,096
  bodies, **8,386,560 pairs a step**, 60 steps a second.

Per pair: a subtraction for $\mathbf r$, a sum of squares, one **square root**,
one **division**, and a few multiplies to scale $\mathbf r$ and add the result
to each body. The square root and division are the expensive part.

### The technique: SIMD

A CPU's vector (SIMD) instructions do the same operation on several
numbers at once: one `fsqrt.4s` takes four square roots. If four pairs'
worth of numbers sit side by side, four pairs cost about what one did.

- Vector width depends on the hardware: 128 bits (four `f32`) on ARM's
  NEON, in WebAssembly's `simd128` and in baseline x86-64; 256 bits with
  AVX2; 512 with AVX-512.
- The compiler does the vectorizing (no intrinsics here); the work is
  arranging the loop so it can.
- **The catch: the sum.** Body i's total force is a sum over every
  other body. Floating-point addition isn't associative, so adding in a
  different order gives different last bits, and the compiler won't
  reorder it on its own. The engine's results must be bit-identical
  natively and in WebAssembly, so the new order is written into the
  source: body i's sum is kept in 16 partial sums ("lanes"), added
  together in a fixed order at the end.

## The loop, before and after

In Rust first. **Before**, the pair loop as it was: one pair at a time,
body $i$'s sum added in order, and a branch for the 0/0 case. **After**,
the first of two passes: every pair's force for body $i$, nothing summed
across pairs (so the compiler can do four at once), the branch a select,
and each force kept in `fx` / `fy`. A second pass then adds those up in
16 partial sums, in a fixed order.

<div>

**Before**

```rust
let mut sum_i = *a_i;
for (a_j, &(x_j, m_j, w_j)) in
    acc_tail.iter_mut().zip(body_tail)
{
    let r = x_j - x_i;
    let d_sq = r.length_sq() + g.softening_sq;
    if d_sq == S::ZERO {
        continue; // coincident: skip, not 0/0
    }
    let f = r * (g.g_const * m_i * m_j
        / (d_sq * d_sq.sqrt()));
    sum_i += f * w_i; // body i, in order
    *a_j -= f * w_j; // body j
}
*a_i = sum_i;
```

</div>
<div>

**After** (pass one)

```rust
let others = xs.iter().zip(ys).zip(ms).zip(ws);
let kept = fx.iter_mut().zip(fy.iter_mut());
for ((a_j, (((&px_j, &py_j), &m_j), &w_j)),
     (fx_j, fy_j)) in acc.iter_mut().zip(others).zip(kept)
{
    let (rx, ry) = (px_j - px_i, py_j - py_i);
    let d_sq = rx * rx + ry * ry + eps_sq;
    let s = g_mi * m_j / (d_sq * d_sq.sqrt());
    // coincident: 0/0, selected away (no branch)
    let s = if d_sq == S::ZERO { S::ZERO } else { s };
    let (f_x, f_y) = (rx * s, ry * s);
    a_j.x -= f_x * w_j; // body j
    a_j.y -= f_y * w_j;
    (*fx_j, *fy_j) = (f_x, f_y); // kept for body i
}
```

Then the same loops as the compiler built them, `f32` on an Apple M4
(AArch64). **Before**, one pair an iteration: the 2-wide vectors
(`.2s`) hold only that pair's $x$ and $y$, the square root and division
are scalar (`fsqrt s16`, `fdiv s5`), and `fcmp` / `b.eq` is a branch that
skips two bodies exactly on top of each other with no softening (0/0).
**After**, four pairs an iteration (`.4s`): four square roots and four
divisions in one instruction each; the branch became a select (`fcmeq`
and `bic` zero those pairs' force); `ld2` / `st2` split and rejoin the
bodies' $x$ and $y$; and each pair's force is kept (`str`) for a second
pass that adds body $i$'s sum in its 16 lanes.

**Before:** one pair an iteration

```asm
	cmp x1, x15
	b.eq LBB193_53

	ldr d4, [x11, x17]

	fmul.2s v5, v4, v4
	faddp.2s s5, v5         ; |r|²
	fadd s5, s9, s5         ; + ε²
	add x17, x17, #16
	fcmp s5, #0.0           ; 0/0?
	b.eq LBB193_57          ;   skip
	add x17, x12, x16, lsl #4
	ldp s7, s6, [x17, #8]
	fmul s7, s3, s7
	fsqrt s16, s5           ; 1 sqrt
	fmul s5, s5, s16
	fdiv s5, s7, s5         ; 1 div
	fmul.2s v4, v4, v5[0]   ; force
	fmul.2s v5, v4, v2[0]

	fmul.2s v4, v4, v6[0]
```

```asm
LBB95_8:
	ldr q7, [x17], #16      ; 4 x
	ldr q16, [x0], #16      ; 4 y
	ldr q17, [x1], #16      ; 4 masses
	ldr q18, [x3], #16      ; 4 1/masses
	fsub.4s v7, v7, v4      ; 4 r.x
	fsub.4s v16, v16, v5    ; 4 r.y
	fmul.4s v19, v7, v7
	fmul.4s v20, v16, v16
	fadd.4s v19, v19, v20   ; 4 |r|²
	fadd.4s v19, v6, v19    ; + ε²
	fmul.4s v17, v17, v2[0]
	fsqrt.4s v20, v19       ; 4 sqrts
	fmul.4s v20, v19, v20
	fdiv.4s v17, v17, v20   ; 4 divs
	fcmeq.4s v19, v19, #0.0 ; 0/0?
	bic.16b v17, v17, v19   ;   select
	fmul.4s v7, v7, v17     ; 4 forces
	fmul.4s v16, v16, v17
	fmul.4s v17, v18, v7
	ld2.4s { v19, v20 }, [x16]
	fsub.4s v21, v19, v17
	fmul.4s v17, v18, v16
	fsub.4s v22, v20, v17
	st2.4s { v21, v22 }, [x16], #32 ; j's
	str q7, [x4], #16       ; kept for
	str q16, [x5], #16      ;   i's sum
	subs x6, x6, #4
	b.ne LBB95_8
```

## Benchmarks

4,096 bodies, one call of the gravity loop (8.4 million pairs), before →
after. Native builds are the default (baseline) build unless noted;
"wasm" is the same Rust compiled to WebAssembly with `simd128`, run by
wasmtime or by V8, Chrome's engine (Node).

| Machine                   | Build           | `f32`                  | `f64`                   |
| ------------------------- | --------------- | ---------------------- | ----------------------- |
| AMD Ryzen 7 9700X (Zen 5) | native          | 13.42 → 4.68 ms (−65%) | 18.74 → 10.88 ms (−42%) |
|                           | native, AVX2    | 13.16 → 2.79 ms (−79%) | 18.70 → 6.67 ms (−64%)  |
|                           | native, AVX-512 | 13.14 → 1.58 ms (−88%) | 18.75 → 3.20 ms (−83%)  |
|                           | wasm, wasmtime  | 14.35 → 4.67 ms (−67%) | 18.72 → 10.92 ms (−42%) |
|                           | wasm, V8        | 22.23 → 4.72 ms (−79%) | 18.72 → 10.88 ms (−42%) |
| Apple M4                  | native          | 8.77 → 4.28 ms (−51%)  | 8.72 → 8.61 ms (−1%)    |
|                           | wasm, wasmtime  | 10.52 → 4.43 ms (−58%) | 9.82 → 8.71 ms (−11%)   |
|                           | wasm, V8        | 10.55 → 4.33 ms (−59%) | 10.65 → 8.30 ms (−22%)  |
